### Overview 
- EtherCAT is:
	- a Beckhoff invention from 2003 
	- the fastest industrial ethernet based fieldbus
	- Real-Time, Deterministic, Synchronized Protocol
	- Improves on the downfalls of ethernet based fieldbus
	
- Main Performance Problems that ethernet based fieldbuses usually have (which are fixed by EtherCAT)
	- Bandwidth Utilization
		- Minimal Application Data Ratio
	- Stack Delays
		- Industrial ethernet Protocol stacks are usually big and processing them takes time 
	- Switch Delays
		- Unpredictable hardware delays 
- EtherCAT improves these inefficiences by
	- **Bandwidth Utilization:** Sending a frame for each communicaiton
		- only 1 frame is generated by the master per cycle and goes to each slave directly
		- all data for whole network is on same frame
	- **Stack Delays:** Data Processing in slave
		- EtherCAT works down to the I/O Level; data is handled in hardware directly
		- Ethernet on the fly reduces stack delays
	- **Switch Delays:** Data Processing in switches 
		- No switches means no switch delays 
		- Message is not routed because everyone gets it and knows where their data lies
			- 1 microsecond forwarding delay

#### Functioning Principles

- key functional principle lies in how it's nodes process ethercat frames
	- each node reads the data addressed to it and writes it's data to the frame as it moves past
- the ethercat frame consitis of 1 or more datagrams
	- datagram - portion of info assigned to a hardware component in the topology 
		- since these contain all the info the master can decided how large of sample it needs
- can connect up to 65535 devices
	- tested with up to 10,000 devices
- machine structure determines network topology 
	- ethercat can find it's way thru the network without caring about how you connect the different devices
- Ethercat uses an internal ring topology to connect independent of the 
	- ![Pasted image 20260120155929.png](/img/user/Knowledge/Pasted%20image%2020260120155929.png)
	- at each device EtherCAT asks if there is another device conected to the existing one and will follow that branch until it ends and then goes back until all the branches are connected.
- this internal ring topology is possible because of the design of the slave controllers 
	- ![Port-Assignments_EK1100.png](/img/user/Knowledge/Port-Assignments_EK1100.png)
	- the slave controller contains 4 ports 
		- Port 0 (A)
			- incoming connection and always needed
		- Port 1 (B)
			-  is open if we have a terminal block connected to the copler 
			- if there is no terminal block then B is closed and has to route to Port C
		- Port 2 (C)
			- if another device is connected then this port is open and the ring can continue thru to the next controller
		- Port 3 (D)
			- Because of the physical design of this coupler is always closed since it is not accessible from the outside
	- Other types of slave controllers
		- ![Port-Assignment_ELxxxx.png](/img/user/Knowledge/Port-Assignment_ELxxxx.png)
			- 
		- ![Port-Assignment_EK1110.png](/img/user/Knowledge/Port-Assignment_EK1110.png)
			- End junction: found at the end of din rail
		- ![Port-Assignments_EK1122.png](/img/user/Knowledge/Port-Assignments_EK1122.png)
	- Remember the ports because they are referenced in debug messages 
		- ![Auto-Config_Ports.png](/img/user/Knowledge/Auto-Config_Ports.png)

- Ethercat State Machine 
	- before a hardware device can communicate w/ field bus it has to go thru this Ethercat state machine
	- ![Ethercat-StateMachine.png](/img/user/Knowledge/Ethercat-StateMachine.png)
		- **Initiate:** No communication is occurring with the slave 
		- **Pre-Operational:** Mailbox communication isused to setup slave parameters
		- **Safe-Operational:** cyclic inputs are exchanged between master and slave 
		- **Operational:**  Cyclic Outpus are exchanged between master and slave
- Distributed Clock (DC) Functionality 
	- DC functionality is what makes Ethercat highly synchronized 
	- these specialized controllers help to monitor and calculate the propagation delay to sync the different slaves
	- Ethercat synchronizes clocks to a system accuracy of <100ns (nanoseconds)
- Safety Over EtherCAT (FSoE)
	- industrial safety protocol 
	- Beckhoff devices that support this are known as TwinCAT devices

#### Summary and Advantages of EtherCAT
- Why use EtherCAT
	- Performance Ethercat has the fastest bus update rates
	- reduces load on cpu by up to 20%
	- supports all common fieldbus and ethernet systems
	- rich diagnostics
	- no need for addressing
- EtherCAT increases Control system Speed

### General EtherCAT Navigation
- Devices can be added either manually or by scanning the connected devices on you're machine
	- Manually can be added without the device existing to prebuild or test out different hardware configs before having to buy the components
	- Scanning requires the devices to be connected and not all devices can be added by scanning
- Identification of EtherCAT Tree Structure
	- top to bottom == Left to Right on the actual controller

### EtherCAT Slave Parameterization
- CoE - CANopen over ethercat 
- edits and changes how the device interprets data 
	- these parameters stay changed until you or the project edit it.
- Terminals with editable parameters will have a 'CoE-Online' tab when selected 
- info on each parameter will be found in the induvial device's documentation
- changes made in the CoE-Online remain with the device even after power cycling
	- this can cause problems with replacing devices so you should use the 'Startup' tab to save custom parameters to the project instead of just to the device
